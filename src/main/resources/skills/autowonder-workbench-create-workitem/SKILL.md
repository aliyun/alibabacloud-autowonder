# AutoWonder 工作台智能新建工单

用于个人工作台「新建工单 → 智能创建」入口。只使用已注入的 autowonder MCP 工具，不新建流程引擎、查重算法或调度器。

## 流程

1. **收集目标**：先听一句话目标与已有背景，整理标题、核心问题与最小可验收结果。信息够用就继续，只追问影响执行的关键问题。
2. **有边界检索**：按核心关键词或工单 ID 调用 `autowonder.list_workitems` / `autowonder.get_workitem` 在当前空间与授权范围内查找少量相关工单；不全量拉取历史。
3. **查重**：发现疑似重复时，给出对方工单链接、状态与简短差异，让用户决定打开已有工单还是继续创建；不擅自合并、取消或宣称检索完整。
4. **代码证据（仅在涉及代码时）**：仅读取直接相关仓库与代码，结论附路径与版本；无权限或检索失败时如实标注“未核实”，不启动开发流程。
5. **生成草稿**：给出可编辑的标题与正文。按现有小队/数字员工及其职责、在线情况建议指派对象；不杜撰人员，不替用户选择 SDLC。
6. **一次集中确认**：确认内容、是否指派、立即启动还是定时启动（时间按 Asia/Shanghai 北京时间展示与校验，必须是未来时间），以及是由真人接手还是由数字员工执行。使用平台现有冻结参数行动计划与用户确认机制执行；未经确认不写入、不指派、不启动。
7. **执行**：
   - 无附件且一次性确认时，直接调用 `autowonder.create_workitem`，按确认结果传 `assigneeType`、`assigneeRef`、`squadId`、`scheduledStartAt`；不传时只创建。
   - 有附件时先创建未派发工单，上传并核验附件后再指派；上传必须先于数字员工派发。
   - 只创建分支不意外派发；创建结果不明时先查询真实结果，不重复创建。
8. **回报**：成功后显示真实工单 ID、链接、负责人与启动安排。已创建但后续指派/定时失败时保留已有 ID，报告部分完成，不重建工单，不把“请求受理”说成“已经执行成功”。

## 边界

- 不展示冗长推理、全部代码或大量工单列表；检索与代码分析设置有限范围，避免无边界循环调用。
- 不新增工单状态、调度或权限逻辑；写操作一律复用既有工具与确认机制。
- 失败项显式标注，允许用户把已确认的标题和正文带回默认创建继续。
