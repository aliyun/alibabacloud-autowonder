# 执行器实时预览专用中转

Vite、项目文件及业务后端代理继续在执行器上运行。浏览器沿用平台 `/design-preview/<bindingId>/...`，平台复用已有成员/分享授权、入口码与短期预览 Cookie。此实现只转发登记的设计预览，不接受平台指定任意主机、端口、TCP 连接或上游 URL。

已核对现有执行器接入：已有 WebSocket 用于任务控制、派单及事件投递，没有可直接复用的 HTTP 字节流、HMR 转发和流控协议。因此复用现有执行器认证，新增独立预览连接，避免预览资源占用任务控制连接。

## 接入与配置

托管试用默认由平台分配绑定。仅在需要手工接入已有预览服务时，参考 [绑定配置示例](../deploy/design-preview/application.example.yml)，完整固定工作区、需求、会话、执行器与 sourceKey。执行器使用 [配置示例](../deploy/design-preview/relay-executor.example.json)，Token 从现有执行器安全环境 `AUTOWONDER_EXECUTOR_TOKEN` 读取，复用 `ExecutorWsAuthenticator`；不需要新的 Basic 凭据。外部入口只接受 WSS；明文 WS 仅允许 localhost、127.0.0.1 或 ::1，用于开发。证书验证开启，不跟随重定向，不使用代理 agent。

需要使用独立安装的兼容 CLI 时，将平台绑定中的 `executor-cli-path` 设为该可执行文件的绝对路径。不设置时沿用执行器的 `autowonder`。

所有执行器默认允许实时预览。单实例部署默认沿用平台的公开 HTTPS 地址，本机也可使用回环 HTTP 地址。平台按数字员工归属、在线状态与执行器声明的能力派发任务，按已保存的设计会话校验预览连接。通过获准安装包的 `autowonder connect` 启动时，执行器使用同一包内的 CLI。其他受控启动方式可用 `AUTOWONDER_PREVIEW_CLI` 指定获准使用的预览 CLI 的绝对路径。支持托管的执行器声明 `PRD_PREVIEW_RECOVERY_V2`。平台根据设计会话和源码目标分配预览子路径，现有手工绑定优先。新设计和评审交付使用自动绑定。

设计 Agent 安装依赖后上报 `PREPARED`，平台经已认证的执行器连接发出启动请求。执行器从该会话的应用目录读取 Vite 配置，监听回环地址，读取实际端口并注册中转。Vite 退出时，执行器优先恢复到上次的端口，如遇占用由 Vite 选择可用端口。中转以同一绑定重新注册，平台只接收当前控制连接的端口上报。已有设计的工作台可请求补做恢复。只读分享页只读取状态。

正式 Spring Boot 启动时，控制/数据中转与浏览器网关分别使用唯一的 Servlet 过滤器名 `designPreviewRelay`、`designPreviewGateway`，顺序为 -202、-201，先于应用的 API 鉴权处理各自的专用路径。两者仅接管各自预览前缀并执行执行器或预览会话鉴权，其余请求继续走原登录链。自定义登录过滤顺序时必须保持这一关系；不能通过关闭平台登录来解决预览握手重定向。跨仓库回归使用正式 FilterRegistrationBean 注册并模拟后续登录重定向，覆盖重复注册名和顺序错误。

```bash
# Token 由已有执行器环境注入；以下命令不携带凭据。
pnpm dev:autowonder --base /design-preview/design-123/
autowonder preview start --id design-123 --port 5173 --config /absolute/private/preview.json --json
autowonder preview status --id design-123 --json
autowonder preview stop --id design-123 --json
```

Vite 必须使用配置中的绑定 base，路由器使用 `import.meta.env.BASE_URL`。实际端口变化须先停止所属 ID，再登记新端口。CLI 固定请求 `127.0.0.1:<登记端口>`，不会执行平台代理传来的目标地址，也不跟随 Vite 的 HTTP 重定向。真实业务认证由工程自己的 Vite proxy 配置提供；平台 Cookie、Bearer、转发头、代理认证头不会进入执行器，响应 Set-Cookie 不会进入平台。共享 origin 的预览脚本仍须可信，不能将这些措施称为浏览器脚本隔离。

## v1 协议

1. CLI 主动连接 `/design-preview-relay/v1/control/<bindingId>`。Authorization 使用 Bearer 执行器 Token，`X-Autowonder-Executor` 必须匹配绑定的执行器 ID。平台认证成功后占用该绑定；重复连接返回 409，不替换当前连接。执行器只回传健康报告或单流容量拒绝；容量拒绝仅回收对应请求，不关闭其他流。
2. 执行器每 2 秒 GET 本机 Vite 的绑定根路径，报告 `health {available}`；平台返回 `registered {available}`。READY 要求本机探活成功且已收到平台注册确认；平台心跳超过 8 秒失效，CLI 注册确认超过 7 秒失效。平台每 30 秒复核执行器凭据；删除绑定或凭据失效会关闭其所属连接。浏览器授权继续逐请求检查，已连接 HMR 最多约 2 秒复核一次。
3. 对每个已授权的 HTTP/HMR 请求，平台创建随机流 ID 和单次短期密钥，经控制连接发送 `open {id,key,kind}`。执行器主动建立同源 `/design-preview-relay/v1/data/<id>` WebSocket，密钥只放 Authorization。流只属于创建它的控制连接代次；不可跨绑定、重复认领或在控制连接断开后认领。待连接流 5 秒超时。
4. 数据连接上，平台发送 `request {kind,method,path,headers}`，随后二进制请求体块和 `end`。执行器返回 `response {status,headers}`、二进制响应体块和 `end`。路径与查询字符串保持原样，响应支持二进制与持续分块；本机同服务重定向转换为平台绑定内路径。编码信息保留，逐跳响应头及其 Connection 指定头剥离。
5. 每个二进制块收到 `ack` 后才能发送下一块，两方向独立。HMR 数据连接的 `opened` 表示本机 WebSocket 已升级；文本使用 `text {data}`，二进制原样传输，两方向同样逐消息确认。任一侧关闭、取消、写失败或确认超时，释放该流和本机连接。平台先经有序控制连接发送 `cancel {id}`，再释放该流的并发名额，使下一条 `open` 不会抢在执行器释放旧流之前到达；未知或重复取消只影响所属控制连接中的该流。控制断开清理该代次全部流，不回放中断的 API 请求。重连建立新代次，浏览器可重新请求。

每个请求独立的数据 WSS 避免一个大资源占满其他会话的队列；执行器不开放接收入站流量的端口。CLI 仅在回环地址提供带随机密码的本机状态检查，不提供反向路由入口。

支持资源流式转发的 CLI 对每个浏览器资源请求只调用一次 Vite。小响应复用控制连接，较大的响应从同一个 Vite 请求续传到独立数据连接，使用有界队列和 TCP 背压控制发送速度。业务请求、HMR 和较早版本的 CLI 沿用各自的流式协议。通过平台鉴权后，浏览器可在私有缓存中短时复用 Vite 标为不可变的带版本依赖，缓存有效期为 60 秒。

同一个在线绑定重新打开 Vite 页面时，入口 HTML 会预加载此前成功读取的源码模块，让浏览器并行请求。预加载地址来自本代连接内该绑定的成功响应，最多保留 160 个，同一个绑定至少间隔 1.5 秒发出一组。Vite 用 `no-cache` 和 `ETag` 返回的 JavaScript 源码模块可以保存在浏览器私有缓存中，每次复用都经过平台鉴权和 Vite 校验。Vite 确认内容未变时返回 `304`，源码变化时返回新内容，HMR 的版本时间戳照常转发。预览 HTML 和业务 API 继续使用 `no-store`。

同源的成员工作台首次打开时，请求预览会话接口即可获知实时状态。预览就绪且成员有访问权限时，接口直接设置路径限定到该绑定的预览 Cookie，预览框随后只加载一次目标页面。分享链接和后续会话续期沿用一次性授权码。

## 限制与状态

- 每绑定最多 24 条数据流（含 HMR），平台最多 128 条，最多 128 个控制连接；为默认 200 线程的 Servlet 连接器留出数据握手余量。超限 HTTP 返回 503；协议非法、超大帧或不遵守确认机制的连接关闭。
- 二进制块 64 KiB，文本帧 128 KiB，平台写缓冲 256 KiB，响应接收队列最多 3 帧；CLI 的 HMR 待发送队列最多 2 帧。HTTP 请求体最多 32 MiB，超限返回 413。
- 数据写/确认期限 5 秒，HTTP 无数据期限 30 秒，HTTP 最长 10 分钟；流式响应不整体缓存。长期无数据的 SSE 需在期限内发送保活，持续时间到期后由业务重新连接。HMR 不使用 HTTP 空闲超时。
- CLI 状态：STARTING、READY、RECONNECTING、LOCAL_SERVICE_UNAVAILABLE、FAILED、STOPPED。认证失败/冲突为终态，网络失败有抖动、最大 5 秒退避重连。平台不可达时 start 最多等待 15 秒，返回真实重连状态并保留监督进程，不伪报 READY。
- 重连若遇到旧连接仍占用的 409，先给平台 8 秒心跳租约失效留出余量；冲突持续超过 10 秒后下一次尝试才进入 FAILED。不会覆盖其他有效连接。start 在等待结束前可返回 RECONNECTING，不能作为已就绪交付。
- 幂等启动只复用配置和 owner 相同的实例。状态目录 0700、状态文件 0600，不持久化执行器 Token；进程指纹防止误杀复用 PID。daemon 注入所属 PID；任务结束后保留，所属执行器退出后清理。托管模式沿用 macOS/Linux，Windows 托管启动仍明确拒绝。
- CLI 内置独立监督进程，转发子进程崩溃/异常终止或健康更新停滞超过 15 秒时自动重启，退避最高 5 秒；卡死子进程先终止，2.5 秒后强制清理。明确 stop 先持久化停止意图，认证失败/绑定冲突保持终态，不自动拉起。执行器启动时间使用固定 UTC/C locale，查询失败视为未知而非已退出；持续未知 10 秒暂停转发，身份重新确认后自动恢复，确认退出则清理。状态保留最近 12 条脱敏事件及重启计数，可区分 OWNER_EXITED、EXPLICIT_STOP、WORKER_SIGNAL_* 和 WORKER_HEARTBEAT_TIMEOUT。
- 启动时先登记监督进程的 PID/指纹，再通过私有 stdin 屏障允许初始化。慢启动返回真实 RECONNECTING，重复 start 不会删除仍在启动的状态或建立重复连接。
- 监督进程被 SIGKILL 时，转发子进程在健康检查中发现实际父进程变化，释放全部连接后退出，避免孤儿持续占用绑定；此时 status 返回 FAILED，重新 start 回收失效状态并建立新连接。此情形不承诺监督进程自身自动重启。
- 打开设计页每 5 秒查询状态，恢复后申请入口码，12 分钟刷新会话。自动恢复使用已就绪的运行记录，无需再发 AI 消息。未登记连接、Vite 不可用、运行记录未就绪、执行器离线或版本不支持时，页面显示相应状态。
- 活跃页面续期 POST 到绑定内 `_autowonder/renew`，使用新的一次性入口码和当前 HttpOnly 预览 Cookie，校验 Origin、用户、成员/分享种类、分享版本和绑定归属。延长同一 SESSION 的有效期并重设 Cookie，返回 204；不会导航 iframe，现有 HMR 连接继续使用同一个授权标识。Cookie 已过期或续期失败时，重新申请入口码并走原进入流程恢复。续期不能用其他用户、分享或绑定的授权替换当前会话，也不放宽账户/分享撤销检查。
- 入口代理的两个 WebSocket 路径均需使用较长读取超时，示例均为 3600 秒；执行器数据连接也承载空闲 HMR，不能套用 HTTP 30 秒无数据期限。入口代理仍可能关闭超过其空闲期限的连接，正式 TLS/代理链路须另验。

## 多实例接入

启用 `autowonder.design-preview.cluster.enabled` 后，负载均衡可将浏览器请求、执行器控制和数据连接分别送到不同平台实例。所有实例使用相同 Redis 和环境专用的 `cluster.namespace`，各自配置唯一的 `cluster.node`，并用 `cluster.peers` 提供每台实例的直连地址。环境级配置可在所有实例共享同一份地址表，运行时自动排除本机条目。新实例接收流量前，现有实例应能解析并访问它的地址。入口域名、子路径和 CLI 协议保持原样。

- 执行器认证后获得 8 秒所有权租约，用健康报告续期。Redis 保存持有实例、连接代次和就绪状态。实例退出后租约自动失效，执行器重连即可注册。旧连接只能续期或释放自己的租约。
- 每次发起转发前，持有实例登记短期数据流 ID，任一入口实例都能把执行器的数据 WebSocket 交给持有实例。浏览器预览和 HMR 也转到同一持有实例。实例间 HTTP 保持流式传输，WebSocket 保持双向通信。Redis 不存放请求体、响应体、预览会话 Cookie 或执行器凭据。
- 转发只允许一跳并校验当前连接代次。持有实例继续校验预览 Cookie 或单次数据流凭据。浏览器转发只携带该绑定的预览 Cookie，执行器数据转发只携带该流的单次凭据。实例直连地址要使用获准承载这些凭据的内部网络，跨信任边界时使用 HTTPS。
- 打开工单触发恢复时使用现有执行器消息通道。接收实例校验工作区和当前连接身份，多个页面的同一轮恢复请求共享去重状态。故障切换期间已经中断的业务请求由客户端按需重试。
- 多实例开关默认关闭。启用后 Redis 不可读时，新的预览请求暂时不可用，避免不同实例同时持有同一预览。正式开启前验证所有实例双向直连、流式刷新、WebSocket 升级和空闲连接超时。

## 验证

通过 [PRD 试用分支](community/prd-design-trial.md) 的工单启动原型，确认打开预览页、选择元素、
提交评审评论和执行器交付。核对两个预览路径均能进行 WebSocket 升级。

预览中转随设计任务自动启动。回环验证覆盖本机代理协议和预览流程，日常环境的实例互访和入口代理需要在该环境验证。

预览首屏 HTML 或必需脚本因 401/403/502/503/504 失败时，尚未初始化的页面按 1、2、4 秒间隔最多自动恢复三次，每次重新申请入口码。已初始化的应用或已收到协作通信就绪消息后，不因后续脚本失败自动刷新，避免重放业务操作。此恢复依赖同源 Performance 条目的响应状态；不支持该信息的浏览器仍可使用手动重试。网关自身的 503 通过 `X-Autowonder-Preview-Error` 区分连接状态与容量拒绝，便于定位；该诊断不包含凭据。
