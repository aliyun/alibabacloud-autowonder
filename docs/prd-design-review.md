# 产品与交互设计实时评审

工作台与分享页统一通过平台主域子路径代理执行器 Vite，右侧浏览器铺满面板，不提供设备尺寸切换。进入工作台自动收起平台导航，可随时展开，不改变其他页面的导航偏好；对话与预览分别滚动，输入区固定在对话底部，设计配置和长回复按需展开。

版本历史和目标项目使用页头紧凑工具入口；待澄清问题放在设计对话标题旁，点击展开问题列表，确认版本时仍校验未解决问题。预览离线时在画布中央显示连接说明和重试操作，工作台和分享页复用同一空状态，不再叠加整行离线提示。输入区使用无外框文本区域，聚焦时仅加强顶部边线，附件与发送按钮保持等高对齐。

点击工具栏的分享直接打开新标签页，首次分享由有管理权限的用户自动开启，无须再经过弹层确认。分享保留当前页面路径、查询参数和 hash；复制链接、关闭分享和重新生成链接位于相邻的更多菜单，重新生成仍需确认旧链接失效。分享页让设计内容铺满窗口，不显示平台外框、品牌标题或浏览器地址栏；圈选与评论工具悬浮在右下角，评论列表默认收起，展开时浮于内容上方，不压缩页面宽度。评审对象是正在运行的设计工程，不是固定发布版本。

设计页左上角可设置唯一的分享英文名，格式为 3–40 位小写字母、数字或连字符，首尾为字母或数字。保存后名称固定。根路由链接形如 `/design-reviews/checkout-redesign`，业务子路由通过原有 `route` 参数保留。英文名与随机链接共享同一授权和评论记录。关闭分享后两者失效，重新启用先确认已发出的英文名链接将恢复访问。轮换只更新随机链接。

英文名和分享关联保存在工单已有的 PRD 设计记录中（`prd_design.review_slug`、`prd_design.review_share_id`），可在开启分享前设置。随机链接的标识继续保存在分享记录中（`prd_review_share.token`）。

## 正式设计评审

设计页的需求说明来自已保存的 PRD 版本。可从对话打开或下载 Markdown。提交设计评审时选择至少一名有 PRD 写权限的空间成员，平台先冻结需求说明并创建 Git 快照，再通知评审人。首个有效的通过或退回决定生效。发起人可在作出决定前撤回。

推送 Git 快照并核对远端分支后，评审人才能作出决定。通过后，同一份已确认的需求说明归档为工单附件。失败可按原快照重试。成功后，需求与设计区域显示交付记录及进入需求澄清的入口。相关社区迁移包括 [V126](migration/V126__prd_design_review_slug.sql)、[V127](migration/V127__repo_design_base.sql) 和 [V128](migration/V128__prd_design_handoff.sql)。

有效登录用户持链接即可查看和评论，无须加入需求所在空间；分享授权仅限绑定的需求、设计会话和工程来源，不改变成员权限。创建、撤销、重新生成分享及向执行器发送意见仍需原有 PRD 写权限。关闭或轮换分享立即阻止新预览请求，已连接的 WebSocket 在下一次授权检查（最多约 2 秒）关闭。禁用账号或要求补充邮箱验证同样使预览会话失效。

## 评论闭环

圈选使用模板现有 inspector 通信，不调用 UXer 业务接口。评论持久化包含作者、路由、选择器、元素摘要/锚点和创建时设计版本。工作台圈选保存后加入输入区引用；评审页只保存意见。负责人可以在面板多选、移除引用和补充说明后统一发送。历史对话保存发送时快照，后续编辑不改写历史；失败保留输入和引用，重试复用消息幂等标识。发送不会自动解决意见。

作者可编辑、删除、解决及重新打开自己的评论；PRD 写权限成员可以删除和管理解决状态，不能改写其他作者正文。修改要求携带当前 version，并发冲突保留输入并提示重新读取。列表支持全部、未解决、已解决及“我的”；点击意见先恢复完整路由，再定位元素，元素消失时仍保留正文。切换工程来源后旧意见只读展示，不作为新工程的执行输入。首版不包含回复线程、@通知和截图扩展。列表首版每个设计会话最多返回最近 1000 条。

设计执行期间，输入区仍可编写说明、引用评论和添加截图，使用“加入队列”提交；“停止”保留为独立按钮，只作用于当前轮次。队列复用后端已有的顺序执行机制，提交不会中断当前设计。输入区上方按服务端最新历史展示待执行意见的摘要、引用和截图名称；轮到该意见执行时移入对话记录。等待列表不依赖本地存储，刷新后从服务端恢复。它展示最新历史窗口内的排队项（当前最多 50 轮），较早的排队记录仍可通过历史分页查看。成功提交后清空草稿，失败保留说明、截图、评论引用及原消息标识用于重试。停止后的后续调度沿用现有后端行为，本次不增加暂停队列、重排或抢占执行能力。

## 接口与迁移

成员接口：`/api/workitems/{workitemId}/prd/review`，可带 `agentId`。GET 返回上下文；GET `/preview-status` 查询隧道，POST `/preview-session` 申请成员入口码，无须开启分享；`/share` 支持 GET、POST（`rotate=true` 轮换）和 DELETE；`/comments` POST 创建，`/comments/{id}` PATCH 修改及 DELETE（query version）删除。

分享接口：`/api/design-reviews/{token}`，只要求有效登录及有效分享授权，独立于当前空间。GET 评审上下文，GET `/preview-status` 查询实际隧道可达性，POST `/preview-session` 申请入口码；评论接口与成员接口同形。上下文不返回执行器目录、端口、失败诊断或任务身份。

原有 `POST /api/workitems/{id}/prd/conversation` 增加可选 `commentIds`，最多 50 个、不得重复，后端检查需求/会话/工程归属。旧请求不变。发送成功记录关联轮次，不改变解决状态。

发送时完整意见及元素快照保存在对话上下文；历史列表使用独立的限长引用卡片，避免大量长评论使历史响应超限。截断部分以省略号显示，不改变执行器收到的完整意见。

社区迁移 [V122](migration/V122__prd_preview_and_review.sql) 包含分享、评论、短期预览授权与隧道报告表。工单活动启动使用 [V131](migration/V131__workitem_activity_launch.sql)。试用环境升级前按正常数据库变更流程执行尚未应用的迁移。

## 主域子路径预览链路

浏览器 → 平台 `/design-preview/<绑定标识>/` → 专用预览中转 → 执行器主动建立的 WSS → CLI 本机转发 → 执行器 Vite → 项目自己的业务后端代理。配置、协议、状态、运行限制与本机验收命令见 [专用预览中转](prd-preview-relay.md)。现有分享、评论、工作台入口和业务路由保持不变。

一次性入口码有效 60 秒，使用同源 POST 交换 15 分钟的 HttpOnly、Secure（HTTPS）、SameSite=Strict、host-only Cookie；Path 限于绑定前缀。执行器连接复用执行器 Token 认证，平台登录 Cookie 和 Bearer Token 均在预览网关剥离。响应不允许设置平台 Cookie 或认证挑战。

打开已有设计页自动查询连接状态并恢复授权；旧 AI 状态报告仅作审计，不再阻断真实连接恢复。执行器连接、登记的 Vite 或当前运行记录缺失时分别提示原因；浏览器不会擅自在执行器上创建服务，不要求用户再次发送 AI 消息。

预览代码与平台共用浏览器 origin；子路径和 Cookie Path 不构成脚本隔离。预览工程须按可以在平台来源运行的代码管理。转发时剥离凭据不能证明浏览器脚本与平台登录态已隔离。

部署应用后，预览中转仍需在确认平台入口与执行器连接的路由配置后启用。HTTPS、多实例路由与完整业务流程需在目标环境验收。
